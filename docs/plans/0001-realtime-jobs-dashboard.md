# Realtime jobs dashboard implementation plan

## Summary

**Goal:** provide an authenticated, read-only, LAN-accessible real-time view of every `super-plan.json` and task progress stream below a project jobs root.

**Scope:** a built-in Node 18 dashboard server and shell lifecycle helper, a self-contained HTML/CSS/JS UI, registry/log snapshot aggregation, authenticated WebSockets, bootstrap/update/doctor distribution support, router and documentation updates, and integration coverage.

**Out of scope:** job mutation, public hosting, TLS/tunnels, external packages, and changes to terminal summary semantics.

**Success signal:** `serve-jobs.sh` starts one authenticated instance, prints parseable connection JSON, a browser receives current snapshots and live updates, transient malformed files remain visible as warnings without data loss, and both vendored and bootstrapped layouts pass the complete suite.

## Context and Design

The existing visual companion is the local precedent for a Node built-in HTTP/WebSocket server, token bootstrap, session-cookie protection, lifecycle metadata, and static browser assets. `summarize-all-tasks.sh` owns the existing aggregation semantics and must remain behaviorally compatible. The new dashboard is a separate operational companion under `scripts/job-dashboard/`, not a mode of the brainstorm server.

**Architecture:** `serve-jobs.sh` resolves paths, owns per-project runtime metadata, starts or stops `server.cjs`, authenticates `/healthz`, and emits the lifecycle JSON. `server.cjs` validates file paths below the canonical jobs root, builds an immutable snapshot from registries and valid JSONL events, scans signatures on the configured cadence, and broadcasts changes only when content differs. Browser assets render text with DOM text nodes and filter the in-memory snapshot locally. The bootstrap manifest copies the whole dashboard directory without overwriting unrelated runtime state.

**Tech stack / versions:** Bash, Node.js >=18 built-in `http`, `crypto`, `fs`, `path`, `net`, and WebSocket framing; Python 3 helper-backed summary behavior; no package dependency.

**Execution mode:** sequential subagent-driven work with `per_batch` independent review. The core runtime, its behavior tests, and `dev/tests.sh` are shared files, so parallel writers would create unnecessary merge conflicts.

### Flow

1. `tool dashboard` resolves the vendored or flat helper and invokes `serve-jobs.sh`.
2. The helper validates arguments and jobs root, restores or generates owner-only runtime token/instance metadata, launches Node, and verifies keyed `/healthz`.
3. A keyed browser request exchanges its key for a strict HttpOnly session and redirects to a clean root URL.
4. The server publishes an initial immutable snapshot after authenticated same-origin WebSocket upgrade, then broadcasts only changed snapshots after signature scans.
5. `--stop` proves the PID belongs to this dashboard before signal delivery and clears live metadata only.

### Contracts

`serve-jobs.sh` accepts the exact argument contract in the accepted spec and detached startup writes exactly one JSON object to stdout. The snapshot uses the accepted `job-snapshot` version-1 envelope; task progress preserves valid JSONL order, retains at most 200 recent events, and reports malformed input as relative-path warnings. `/`, `/api/snapshot`, `/healthz`, and WebSocket upgrades reveal no job data without the token or session cookie.

**Global constraints:**

- Preserve lifecycle strings and never mutate any file below the selected jobs root.
- Node 18 built-ins only; no CDN or install step.
- Keep `stdout` to the single detached-start JSON object; diagnostics stay on `stderr`.
- Reject unauthorized or cross-origin requests before registry data or a socket is exposed.
- Use project-relative display paths and treat all job content as literal text.
- Behavior changes follow TDD and `docs/context/testing-anti-patterns.md`.

## Risks and Handoff

| Risk | Detection | Mitigation | Rollback / recovery |
| --- | --- | --- | --- |
| Partial job writes | warning snapshot tests | retain per-plan last valid state and rescan | replace malformed source; next scan recovers. |
| LAN exposure | unauthorized/cross-origin tests | token, strict cookie, origin check, headers | stop helper removes listener and live metadata. |
| Flat-layout drift | bootstrap/update fixture tests | one manifest list per helper and doctor verification | update helper stack; runtime state remains intact. |
| Server/process leak | restart/stop tests and health checks | per-instance identifier and safe PID proof | idempotent stop or stale metadata cleanup. |

**Rollout / observability:** opt-in local helper only; warnings and connection metadata provide operator visibility. No migration or external deployment.
