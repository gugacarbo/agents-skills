# Base project conventions

## General

- Use English for code, comments, and durable project documentation.
- Keep the README current.

## Code Style

- Follow the repository formatter and linter.
- Use LF, no trailing whitespace, and one final newline.

## Git

- Use Conventional Commits.
- Never commit secrets or `.env` files.

## CI/CD

- Run available lint, typecheck, test, and build scripts.

## Agent Behavior

- Inspect existing files before changing them.
- Get approval before overwrites or irreversible actions.
- Report completed and skipped checks.

## Project Structure

- Separate source and generated output.
- Track generated output only when project policy requires it.

## Skills

- Use `commit-changes` for commits and `code-flow` for multi-step deliveries.
